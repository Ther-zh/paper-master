# 工作流 W0：输入契约（研究叙事 + 证据）

> 生成模式的起点。目的：把用户的研究成果转成 agent 可消费的结构化输入，避免凭记忆写作。

## 可接受的输入形态（任一）

1. **NARRATIVE_REPORT.md / STORY.md**（最佳）——研究叙事：核心贡献、方法、实验、结果、figure 描述
2. **CLAIMS_FROM_RESULTS.md** —— 已验证的声明列表（每条映射到实验证据）
3. **实验结果目录** `results/*.json|csv|yaml`、`figures/*`、训练日志、wandb 摘要
4. **研究方向 + 口语描述**（最差，需先引导澄清）

## 若输入不足，先问（不要直接写）

- 「你的核心贡献是什么？1-3 句话」
- 「有哪些实验/结果？原始数据文件在哪？」
- 「和现有工作的区别？基线对比数据？」
- 「目标会议/期刊？」

## 产出

写入 `narrative.md`（或直接使用用户的 NARRATIVE_REPORT），结构：

```markdown
# 研究叙事

## 一句话贡献
[用一句话说明本文贡献]

## 目标 venue
[会议/期刊 + 页数限制/模板要求]（W1 结构预算与 W2 写作约定依赖此字段）

## 核心声明 (claims)
1. [claim 1] ← 证据: results/exp1.json (Table 1)
2. [claim 2] ← 证据: 用户确认的理论推导

## 方法概述
[方法框架，2-5 句]

## 实验与结果
| 实验 | 数据文件 | 关键指标 | 基线 |
|------|---------|---------|------|

## 已知局限
[诚实列出，供 Limitations 使用]

## 图表素材
[figure 描述/文件路径]
```

## 铁律

- 叙事里没有的数字、结果、引用，后续阶段一律不得凭空出现
- 若用户只能口头描述结果而无原始数据，明确标注 `[unadjudicated]`，写进论文时用 DATA_NEEDED 占位并提示用户补数据
