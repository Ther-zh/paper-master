# 工作流 W1：规划（叙事策略 + Claims-Evidence + 写法卡 + GAP）

> 生成模式的第二阶段。把研究叙事变成「有证据背书的结构化论文蓝图」。

## Step 0：叙事策略卡（模块13 写入时生效——先定故事，再列 claim）

**不要跳过。** 证据撑不住的故事要在规划时重构，而不是等写完再防御。产出一张卡（并入 `PAPER_PLAN.md`）：

```markdown
# 叙事策略卡
## 核心优势（主叙事，选 1 个）
[最值得发表的价值：新能力 / 新机制 / 更低成本 / 更强适用性 / 更有意义的权衡]
## 本文赢的比赛
[任务定义 / 评价维度 / 应用场景 / 约束 / 比较口径]——不把不占优的指标设为主战场
## 故事线（最终成立逻辑）
问题为什么重要 → 现有方法为什么不够 → 本文提供什么 → 证据如何支持
## 实验职责表
| 实验 | 论证职责（证明方法有效 / 证明机制 / 证明场景价值 / 排除替代解释） |
|------|----------------------------------------------------------------|
## 重构检查
[若现有证据无法支撑原始叙事：重新定义问题 / 重排贡献 / 重选主结果——在此记录，不带到写作阶段]
```

- 素材来自 W0 `narrative.md`；「已知局限」不进入主线叙事，但按模块13 规则 7 如实保留给 Limitations
- 优势必须能被证据牢固支撑（模块13 硬边界：调整的是叙事立场，不是真值）

## Step 0.5：机制注册表 + 术语账本（v3.2 新增，核心）

> **先枚举机制，再写 claim**——否则"看起来小、实际判据多"的模块会在初稿漏掉（Slow/Meta 教训），
> "设计里写了、代码没接"的机制会被默认写成已实现（revision_rounds 教训）。
> 规范与表模板见 **[ledgers.md](ledgers.md)**；三类账本在本步生成，写入 `PAPER_PLAN.md` 附表并贯穿 W2/W5。

1. **机制注册表**：从代码（文件/函数/关键配置项）、实验证据（消融/日志）、narrative 逐条枚举
   全部模块与机制；每条标 core/supporting/baseline + 实现状态与锚点。
   **理论型论文换为定理/假设注册表，实证型换为实验/协议注册表。**
2. **术语账本**：从代码标识符/配置键/实验字段 + narrative 抽取术语，逐条锁定
   "源术语 → 论文用词（replace/define_once/allow）"。
3. **设计-实现差异台账**：凡引用设计文档的机制声明，登记实现状态（已接入/部分/未接入/仅设计）
   + 锚点 + 验证方式（code/user/unknown）。
4. **反向核验**：问一句"哪个机制看起来小但参数/判据/分支多？"——这些必须进 core
   （判据数、分支数、自由参数数、消融拆解、claim 依赖是信号；**代码行数不是**）。

## Step 1：构建 Claims-Evidence Matrix

从 `narrative.md` / `CLAIMS_FROM_RESULTS.md` 提取核心声明并映射证据。
**与机制注册表对齐**：每条核心 claim 回指注册表中的机制/实验条目；回指不上的机制 → 检查是否漏 claim。

```markdown
| Claim | Evidence | Status | Section |
|-------|----------|--------|---------|
| 方法 A 在基准 X 上超过 SOTA 3.2% | results/x.json, Ours vs Best-Baseline | Supported | §4.1 |
| 方法 A 具有理论保证 | 用户确认的引理（定理 1） | Supported (user-verified) | §3 |
| 方法 A 可泛化到新域 | 仅 1 个域验证 | Partial → 弱化为 "on this domain" | §4.3 |
```

状态分类：
- **Supported**：有数据/引用/用户确认的推理支撑
- **Partial**：证据不完整 → 缩小 claim 范围
- **Unsupported**：无证据 → 删除或降级为「未来工作」
- **Unadjudicated**：用户口头声称无原始数据 → 用 `[unadjudicated]` 标注

## Step 1.5：核心 claim 写法卡（模块12 写入时生效——先定怎么写，再动笔）

对 **1–3 条最核心 claim**（勿全部）在 Matrix 旁补写法卡，只选相关做法（模块12 七项做法，勿全套跑）：

| Claim | 研究张力（为何值得研究） | 贡献增量（去掉方法名与 novel 还剩什么） | 证据匹配（被测量/被证明的性质 vs 主张） | 比较口径（决定什么 / 什么固定 / 什么改变） | 适用条件（不可省的 regime / 量词） | 自由参数与敏感性 |
|-------|------------------------|--------------------------------------|------------------------------------|----------------------------------------|--------------------------------|------------------|
| ... | ... | ... | ... | ... | ... | 含自由参数/阈值时必填：敏感性或翻转点；给不出 → claim 限缩为正式口径 |

- 资源型论文补「资源支持的研究」（单位/接口/构建与访问条件/intended vs demonstrated）；结果型补「有边界的认识」
- 张力必须真实：**不得编造**前作失败或理论矛盾；来源不可得时标注为通用研究建议
- 写法卡直接约束 W2 措辞；W5 数值审计与 W2 写作纪律共同兜底
- **自由参数敏感性（v3.2，λ 教训）**：claim 的指标/分数含自由参数、阈值、权重或选取规则时，
  本列必须给出敏感性或翻转点（如 J(λ) 重算 + 与人工基线的翻转点）；给不出 →
  该 claim 只允许写成正式口径（formal setting），不得主张"一致提升"

## Step 2：确定论文类型与结构

> 目标 venue 已在 W0 收集：此处加载其约束（页数预算、结构惯例、风格要点，见模块4 与 venue/ieee.md），让结构在写入时就符合，而不是 W6 再补救。

| 论文类型 | 结构特征 |
|---------|---------|
| 实证型 (empirical) | Intro → Related → Method → Experiments → Discussion |
| 理论型 (theory) | 增加 Notation / Theorem / Proof，正文定理 ↔ 附录全证明 |
| 方法型 (method) | 方法占主导，实验验证核心机制 |

## Step 3：GAP_REPORT（证据缺口报告）

对照论文结构槽位 vs 用户实际证据，逐槽分类：

```markdown
| 结构槽位 | 需要什么 | 用户证据 | 状态 | Slot ID |
|---------|---------|---------|------|---------|
| §4 消融实验 | ablation 矩阵 | 无 | missing | GAP_S4_ABLATION |
| §4.2 缩放规律 | log-N 曲线 | 无 | missing | GAP_S4_SCALING |
| §2 Related | 引用密度 ≥ 60 | bib 35 条 | partial | GAP_S2_CITES |
| §5 失败案例 | failure-case 分析 | narrative 无 | missing | GAP_S5_FAILURE |
```

Slot ID 格式：`GAP_<SECTION>_<FEATURE>`，全大写，保持稳定。

## Step 4：输出

- `PAPER_PLAN.md`：叙事策略卡 + **机制注册表 + 术语账本（附表，见 [ledgers.md](ledgers.md)）** + 分节大纲 + 每节 claim/证据/图表计划 + 核心 claim 写法卡
- `GAP_REPORT.md`：上表（作为 W2 写作的契约）
- 设计-实现差异台账：凡引用设计文档的机制声明逐条登记（可并入注册表附表）

## 硬规则

- **绝不推断、填充、编造证据来「补缺口」**。missing 就是 missing
- 缺口直接暴露给用户，不隐藏、不粉饰
- GAP_REPORT 用于 W2 生成 `<!-- DATA_NEEDED -->` 占位，不用于编造内容
- **账本未建不得进入 W2**（Born-Correct）：注册表缺 core 条目、术语账本缺映射 → 先回 Step 0.5
