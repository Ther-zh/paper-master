# 模块 12：优秀论文对照学习（Oral Exemplar Learning）

> 吸收来源：`oral-paper-skill`（Adkid-Zephyr）——883 篇 ICLR / ICML / NeurIPS Oral 摘要的来源核查与跨论文综合。
> 原始快照（含完整语料、证据卡与提炼过程）见 [external-refs/oral-paper-skill/](../external-refs/oral-paper-skill/)。

**触发意图**：「对照优秀论文」「看看 Oral 论文怎么写」「帮我找可改进点」「学习复盘」「exemplar / oral paper」「这篇工作对标哪篇」「帮我复盘这项工作」

## 边界声明（先读，不可跳过）

- 七项做法是**编辑参考**（editorial moves），不是 883 篇的"共同定律"，不是录用评分表，也不预测录用结果。
- 证据层级 = **摘要级**：可支持 framing、贡献陈述与作者自报证据；实验严谨性、证明正确性、图表设计**必须查原文**再归因。
- 不编造引用；来源不可得时明确标注为「通用研究建议」，不让用户为凑模板去找参考文献。
- 默认最多给 3 条改进建议；没有发现真差距就直说，不发明批评。
- 不要为一次改动重载全部语料；用小的可比范例集，必要时再取深材料。

## 两个服务

### 服务 A：对照改进（Compare & Improve）

1. 先定位草稿的**重要 claim** 及其当前支撑状态。
2. 从七项做法中选 **1–3 项**相关做法 + 1 个在问题/贡献类型/资源上真正可比的范例。
3. 每条建议按六要素输出：**草稿位置 → 来源做法 → 具体改法或下一步检查 → 为什么合适 → 重要限制**。
4. 被要求编辑时：直接给修改文本、图表方案或实验方案；保持 title / abstract / introduction / 主证据一致，不强迫每节重复同一个 claim。
5. 为提议的实验只写改变决策的部分：claim、比较、分析单位、需控制的条件、结果、结果如何改变解读。「全部对齐」可能答错了问题。

### 服务 B：学习复盘（Learn & Reflect）

1. 选**一项**做法 + 一个小例子，讲清其目的与一个重要例外。
2. 给一个针对用户自己段落/比较/计划的聚焦练习。
3. 任何虚构的教学示例或示范改写必须显式标注。
4. 与用户同时要两种服务时，优先产出工件，只讲影响了工件的课程。

## 七项做法（按需选 1–3 项，勿全套跑）

| # | 做法 | 试用方法（Try this） | 何时用 | 例外 |
|---|------|---------------------|--------|------|
| 1 | **写清研究张力**（Specify the research tension） | 用「未满足的条件/要求 + 对研究目标的影响」替换宽泛的重要性或弱点陈述，再接研究问题；疑似解释标为 hypothesis | 描述了宽泛问题，但没说清为什么偏要研究这个 | 探索性问题、资源介绍或聚焦刻画可直接进入；**不编造**前作失败或理论矛盾 |
| 2 | **明确贡献增量**（State the contribution delta） | 用「原有对象/要求 → 精确改变 → 剩余依赖」替换 “a novel framework”；把改变定位到计算或分析中 | 只命名模块或声称 novelty，看不出与相关工作的差别 | 发现或资源不必替代现有方法；假设不变之内的改进按实际描述 |
| 3 | **让证据对应主张**（Match evidence to the claim） | 每个中心 claim 指认「被测量或被证明的性质」；区分尝试与成功、代理指标与整体能力、计划中的评估与已报告结果 | 使用宽泛能力语言，或把多种证据当可互换支撑 | 描述性发现无需干预即可成立，定理无需实验；只补作者想下的主张所需的证据 |
| 4 | **选择有解释力的比较**（Choose a meaningful comparison） | 说明比较要决定什么、什么保持固定、什么改变；效率类给出真实资源单位与核算边界（含调参） | 排名可能来自训练暴露、输入、实现或预算差异，而非所讨论的差异 | 对齐条件可能改变研究问题；比较交付系统本身同样合理；控制一个因素≠所有预算对齐 |
| 5 | **结论紧随适用条件**（Keep conditions beside conclusions） | 改写为「对某对象、在某条件下、某量相对某比较类有此保证」；不同条件的扩展分开写 | 定理、迁移、缩放或范围扩展一旦省略 regime / 量词就变味 | 不发明假设、逆命题或多 regime；缺失摘要细节≠全文缺失论证 |
| 6 | **说明资源支持的研究**（Explain what the resource enables） | 描述资源单位、附加信息或接口、构建与访问条件、支持的研究活动；分开 intended uses 与 demonstrated uses；各工件发布状态独立保留 | 数据集、基准、环境、实现或文档承担部分或全部贡献 | 窄或探索性资源不必带 leaderboard、新模型或下游增益；普通代码发布句不必升格为资源贡献 |
| 7 | **提炼有边界的认识**（Extract a bounded lesson） | 用「学到的具体区分 + 其在所研究场景中的含义」替换泛泛结尾；分开观察、解释与建议行动；指出什么会限制迁移 | 结果或论证支持理解、解释或选择上的改变 | 描述性发现不必给机制或处方；单个有趣案例不等于普适设计规则 |

**七项反思问题**：

1. 哪个具体观察或未满足要求，让我的研究问题值得回答？
2. 去掉方法名和 “novel” 之后，我还能说清改了什么吗？
3. 每个标题级 claim 的确切支撑性质是什么？哪里在用代理指标或未报告的结果？
4. 我的比较解决哪个决策？哪个不同条件会改变解读？
5. 哪个条件或量词一旦被读者漏掉，会实质性放大我的结论？
6. 其他研究者能用这个资源调查、构建或比较什么？哪个特性使这成为可能？
7. 读者读完后应当理解或重新考虑什么？什么会让这个认识失效？

## 按论文类型选择范例（Archetype Guide）

| 类型 | 选择与证据重点 | 不要强求 |
|------|--------------|---------|
| 方法 / 算法 | 改变的操作、表示或能力；意图角色；差异证据 | 每个耦合组件都独立有益；组件归因实验（除非归因本身重要） |
| 理论 | 数学对象、假设、量词、保证、与先前结果的精确比较；充分 vs 必要、上界 vs 匹配界、最优性 regime | 经验 benchmark 胜利；解决长期难题；操作处方 |
| 实证 / 解释 | 观察、协议、相关条件、不确定性；区分描述性发现 / 解释假设 / 模型证据 / 干预 | 新方法或普适机制；非因果主张不要求因果控制 |
| 系统 / 效率 | 接口与组件关系、工作负载、测量资源边界；局部加速 vs 端到端；质量变化 vs 效率收益 | 每个组件都要新颖；交付系统比较不必是组件归因研究 |
| 数据集 / 基准 / 资源 | 单位、构建、覆盖、访问条件、支持的研究活动；测量效度看构念、标签、oracle、捷径 | 附属模型更优；固定答案评分；新机制 |
| Position | 论点、价值前提、论证或证据、类比、迁移限制、建议行动；公平对待反立场 | benchmark 胜利；方法新颖性；完整可执行方案 |

## 溯源纪律（Source Attribution）

- **三分原则**：分开「来源怎么说」「为什么可能有用」「我为这篇草稿提什么」——应用建议 ≠ 原作者做过的实验。
- 给出处时包含：论文标题、链接、检读层级（abstract / full-text-passage / figure）、具体句子或图表编号。范例里的 S3 类编号属于快照分段，不是论文官方章节号。
- 保留后果性限定词：structural-assumption-free ≠ assumption-free；reported maximum error ≠ proved bound；未注明的百分比 ≠ 百分点；future release ≠ 现在可用。
- 来源未说明的事实保持 unknown；不用直觉"修复"，也不把摘要中的缺失当全文缺失。
- 若来源不可得：把建议标注为通用研究建议，**不虚构引文**。
- 深材料优先级：需要实验严谨性或图表设计归因时查该论文原文；需要语料级溯源时查快照内 `research/abstract_distillation/`。

## 复盘检查单（结构化复盘时用）

- 学习目标是什么：framing / 贡献 / 论证顺序 / 图表 / 实验 / 解释？
- 哪些已支撑，哪些仍是想法或材料缺失？
- 哪个范例在问题、贡献类型、资源约束上真正可比？（按类型表选，不按名气选）
- 可选 ORAL 记忆钩子：**O** 中心问题能否说清并且多个贡献如何连接？**R** 主图/定理/表格/演示是否让证据可见？**A** 是否有证据尚未区分的替代解释或混杂？**L** 其他研究者能带走什么？——缺一维不代表不行，这不是评分表。

## 输出格式

```markdown
## 对照改进报告

### 改进建议（默认 ≤ 3 条）
1. **Practice**：来源做法（含证据层级）
   **Source**：论文 + 链接 + 检读位置
   **Relevance**：为何与本稿相关（注明重要差异）
   **Observation**：草稿现状与位置
   **Action**：具体改写 / 图表变更 / 比较或分析
   **Reflection**：一个聚焦问题

### 未发现差距（如适用）
（明确说明，不编造批评）
```

## 逐篇文体卡库（Exemplar Cards）

本库随附 27 张文体参照卡（含 Oral/Best Paper 单篇卡与跨篇奖项卡），覆盖 CVPR / ICCV / ECCV / NeurIPS / ICML / ICLR / ACL / AAAI / ACM MM 等会议。

- **先查目录**：[exemplars/index.md](exemplars/index.md) 列出每张卡的会议、年份、论文与该卡擅长说明的写法。不要遍历 `cards/` 目录。
- **卡的结构**：Story Pattern / Abstract Moves / Introduction Moves / Method Moves / Evidence Moves / Citation Patterns / Reusable Techniques / Do-Not-Copy Boundary。
- **新增一张卡**：`python scripts/convert_pdf_to_card.py <pdf> --output-dir references/exemplars/cards --full-text-dir references/exemplars/papers`，生成骨架后按上面八段逐段填。脚本不自动登记，填完后手工在 `index.md` 加一行；没有填完的卡不要登记。
- **原文不随附**：卡片里提到的 `papers/<slug>.md` 是上游抽取文本，本库未打包。需要原文时按卡片标注的会议/年份/标题自行获取，不要把缺失原文当成卡片失效。
- **使用边界**：借叙事节奏、段落职责与证据组织，不复制原句，不搬运其科学主张。卡片是参照物，不是模板。

与「服务 A/B」「七项做法」的关系：卡片提供**逐篇样例**，本模块的七项做法提供**抽象规则**；两者冲突时以用户论文的真实证据为准。

## 与相关模块协作

- → 模块1（结构策略）：对照结论落到结构槽位；暴露的缺口进 GAP_REPORT
- → 模块2（段落润色）：执行具体改写；改写时叠加模块13 防自我削弱
- → 模块5（审稿预检）：本模块是事前对照学习，模块5 是事后攻防预演
- → 模块8（文献调研）：需要检索范例全文或补引时
- → 模块13（防御性写作阻止）：学习成果落到叙事立场时
- → 生成模式 W1/W2：以七项做法作单点编辑 checklist，不做每篇必过的硬门槛
